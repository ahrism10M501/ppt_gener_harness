# 시각 자료 설계와 제작 연결

Stage 3에서 슬라이드의 주장과 근거를 정할 때 읽는다. Stage 4에서는 그 결정을 제작에 넘기고, 실제 슬라이드에서 설명·배치·결과를 대조한다. 그림이 필요한지, 어떤 표현을 쓸지, 누가 만들지는 이 문서가 기준이다.

## 1. 필요성과 만들 사람

각 핵심 문장에 대해 청중이 눈으로 확인해야 할 관계를 한 문장으로 적는다. 값의 차이, 구조, 인과, 공간 관계, 갱신 순서 같은 것이다. 글이나 작은 표로 충분하면 그림을 만들지 않는다. 순서·구조·분류·대안 비교를 불릿으로만 나열하게 되면 도식을 먼저 검토한다.

먼저 `sources/`와 기존 `figures/`를 확인하고, 적합한 그림은 출처와 조건을 보존해 재사용한다. 웹 사진·논문 figure는 [외부 시각 자료](external-visuals.md)대로 직접 찾는다.

- **요청 없이 만든다:** 승인된 내용을 다시 그리는 흐름도·타임라인·매트릭스·카드. 새 값을 담지 않기 때문이다.
- **요청받은 범위에서 만든다:** 수치 차트(도넛·퍼널·정량 그래프), 새 연구 결과 그래프, GIF. 범위 안에서는 그림마다 다시 묻지 않는다.
- **요청으로 남긴다:** 자료가 없는 수치·오차·결과. 만들지 않는다. 교육용 합성 예제는 합성임을 밝힌다.

## 2. 표현 선택

아래는 출발점이다. 어떤 인상이 어울리는지(상자 모양, 색을 얼마나 쓰는지, 그래프 스타일)는 템플릿의 `templates/<id>/DESIGN.md`로 판단한다.

| 설명할 정보 | 우선 검토할 표현 | 도구 |
| --- | --- | --- |
| 소수의 정확한 값·조건 | 본문 또는 작은 표 | `slides.md` 표 |
| 조건별 차이·분포·추세 | 점·선·막대 정량 그래프 | [scientific-visualization](../../scientific-visualization/SKILL.md) |
| 절차·분기·그룹·피드백·상호작용 | 관계에 맞춘 도식 | [ppt-charts](../../ppt-charts/SKILL.md) `diagrams.py` |
| 비율·순서·분류·대안 비교 | 도넛·타임라인·매트릭스·퍼널·카드 | [ppt-charts](../../ppt-charts/SKILL.md) `charts.py` |
| 기구·센서·하드웨어·다층 시스템의 내부 구조 | 아이소메트릭 해부도 | `uv run pptgen anatomy` ([anatomy](../../anatomy/SKILL.md)) |
| 논문의 복잡한 figure | 원본 재사용·패널 분리·확대 | [외부 시각 자료](external-visuals.md) |
| 단계마다 멈춰 설명할 과정 | 여러 정적 상태·여러 장 | 위 도구 조합 |
| 이동·갱신·시간 변화의 대응 | GIF와 대표 PNG | [ppt-animation](../../ppt-animation/SKILL.md) |

모든 개념을 움직이게 만들지 않는다. 사용자에게 특정 표현의 의도가 있으면 반영하고, 정적 설명이 더 나은 부분은 함께 제안한다. 논문용 작은 글자·외부 테마를 발표에 그대로 옮기지 않는다. 그래프 색은 `rvppt.template.semantic_palette(<preset>)`에서 가져온다.

## 3. 제작에 넘길 요약

`plan/outline.md`의 `figure`에는 표현·근거·재사용/생성 여부를 짧게 적는다. 새로 만드는 그림은 아래에서 필요한 것만 outline 본문이나 노트에 남긴다.

- 주장과 확인 질문: 이 그림을 본 청중이 무엇에 답할 수 있어야 하는가?
- 자료와 범위: 원자료 경로, 단위·비교 조건·변환, 합성 여부, 근거가 없는 부분.
- 필수 시각 요소: 축·점·선·화살표·주석 중 설명에 반드시 필요한 것과 기호의 대응.
- 표현: 정적/여러 상태/GIF를 고른 이유, 피해야 할 오해.
- 배치: 단독인지 본문과 2단인지. 슬롯에 맞는 종횡비와 글자 크기를 고려하고, 텍스트로 남길 수식을 정한다.

예를 들어 경사하강법의 주장이 "기울기와 갱신 방향의 관계"라면 손실 곡선·현재 점·접선·갱신 화살표가 필수 요소다. 곡선이나 움직이는 점만 그렸다고 설명이 완성되지는 않는다.

## 4. 제작

선택한 경로에 필요한 지침만 읽는다. 외부 스킬이 청중·스타일을 다시 묻거나 독립 발표를 만들려 하더라도 이 task의 입력·프리셋·승인을 우선한다. 데이터와 변환은 코드에 연결하고, 도식의 입력·출력·화살표 의미를 검산한다. 실행 도구가 없으면 가능한 정적 작업을 진행하고 설치가 필요하다고 알린다.

## 5. 실제 슬라이드에서 검수

원본 그림만 보고 끝내지 않는다. 빌드한 슬라이드 PNG와 audit 크롭을 본다. audit 크롭은 캡션·출처·GIF 대표 장면까지만 담으므로 그림 안의 축·라벨은 슬라이드 PNG에서 확대해 본다.

- 설계한 시각 요소가 실제로 있고, 수식·기호·숫자·그림이 같은 의미인가?
- 확인 질문에 그림으로 답할 수 있는가? 장식이 핵심 비교를 가리지 않는가?
- 슬롯에 넣은 뒤 축·라벨·범례가 읽히고 캡션·본문과 겹치지 않는가?
- 색 없이도 선 모양·마커·라벨로 구분되는가? 출처와 자료 범위가 남아 있는가?
- GIF의 대표 PNG에도 핵심 의미가 남는가?

표현 자체가 맞지 않으면 설계로 돌아간다. 핵심 주장·순서·근거를 바꾸는 수정은 [워크플로우](../../../docs/workflow.md)의 승인 절차를 따른다.
