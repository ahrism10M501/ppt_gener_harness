# RVLAB 시각 자료 설계와 제작 연결

Stage 3에서 슬라이드의 주장과 근거를 정할 때 읽는다. Stage 4에서는 그 결정을 제작에 넘기고, 실제 슬라이드의 설명·배치와 결과를 대조한다. 청중·목적·승인은 기존 인터뷰 문서에서 가져오며 별도 질문·승인 단계를 만들지 않는다.

외부 사진과 논문 figure가 필요하면 [검색·추출·캡션 기반 선택 절차](external-visuals.md)를 읽는다. 기존 자료를 우선하고, 부족한 설명용 사진은 직접 찾아 넣는다.

## 1. 시각 자료의 필요성과 역할

각 핵심 문장에 대해 청중이 눈으로 확인해야 할 관계를 한 문장으로 적는다. 값의 차이, 구조, 인과, 공간 관계, 갱신 순서처럼 그림이 드러낼 정보를 정한다. 글이나 작은 표로 충분하면 새 그림을 만들지 않는다.

먼저 `sources/`의 논문·데이터·초안 PPT와 기존 `figures/`를 확인한다. 적합한 그림은 출처와 조건을 보존해 재사용하고, 필요하면 패널을 나누거나 설명을 보탠다. 원자료를 고치거나 비교에 필요한 부분을 숨기지 않는다.

새 제작은 사용자가 허용한 범위에서 수행한다. 이미 요청한 그래프·도식·애니메이션 제작 허가를 그림마다 다시 묻지 않는다. 제작 요청이 없는 경우에는 필요한 자료와 그림 요청을 기록한다. 자료가 없으면 수치·오차·연구 결과를 만들지 않는다. 교육용 합성 예제는 명시적으로 구분한다.

## 2. 자료 성격에서 표현을 선택

아래는 출발점이며 도구를 반드시 쓰라는 규칙이 아니다. 표현을 정한 뒤 필요한 스킬의 관련 지침만 읽고 구현 도구를 선택한다.

| 설명할 정보 | 우선 검토할 표현 | 읽을 지침 / 제작 도구 |
| --- | --- | --- |
| 소수의 정확한 값·조건 | 본문 또는 작은 표 | 기존 RVLAB 본문·표 문법 |
| 조건별 차이·분포·추세 | 점·선·막대 등 정량 그래프 | [scientific-visualization](../../scientific-visualization/SKILL.md) / Matplotlib·SciencePlots |
| 비율·순서·분류·전환을 꾸밈 있게 보여 줄 때(도넛·흐름도·타임라인·매트릭스·깔때기·비교 카드) | 고정 팔레트 레시피 | [rvlab-charts](../../rvlab-charts/SKILL.md) / `charts.py` |
| 모듈 구성·입출력·절차 관계 | 정적 직각 도식 | RVLAB 디자인·이 문서 / 기존 Mermaid·SVG·Matplotlib |
| 논문의 복잡한 figure·결과 이미지 | 원본 재사용·패널 분리·확대 영역 | [scientific-slides의 발표용 그림 지침](../../scientific-slides/references/data_visualization_slides.md), PDF 처리 시 [pdf](../../pdf/SKILL.md) |
| 단계마다 발표자가 멈춰 설명할 과정 | 여러 정적 상태 또는 슬라이드 | 기존 RVLAB 그림 배치; 계산·상태 대응은 [rvlab-animation](../../rvlab-animation/SKILL.md) 참고 |
| 이동·갱신·시간 변화의 대응 | GIF와 대표 PNG | [rvlab-animation](../../rvlab-animation/SKILL.md) → 필요한 경우 Manim 장면 기획·CE 구현 지침 |

Manim이나 GIF를 먼저 선택해 모든 개념을 움직이게 만들지 않는다. 사용자에게 특정 표현의 의도가 있으면 반영하되, 정적 설명이 더 적합한 부분은 함께 제안한다. 논문용 작은 글자·외부 테마·여러 색을 발표에 그대로 적용하지 않는다. 스타일은 `DESIGN.md`와 `docs/design/rvlab.mplstyle`을 따른다.

## 3. 제작에 넘길 그림 요약

`plan/outline.md`의 기존 `figure` 문자열에는 표현·근거·재사용/생성 여부·필요한 제작 경로를 적는다. 세부 설계는 outline 본문과 해당 `slides.md` 노트에 둔다. Stage 3의 `review.slides`에 새 필드나 좌표·폰트·색·layout 필드를 추가하지 않는다. 애니메이션의 상세 장면은 기존 `plan/animation.md`를 연결한다.

제작자가 다음을 알 수 있도록 필요한 항목을 요약한다.

- 주장과 확인 질문: 이 그림을 본 청중이 무엇에 답할 수 있어야 하는가?
- 자료와 범위: 원자료 경로, 단위·비교 조건·변환, 합성 여부, 근거가 없는 부분.
- 필수 시각 요소: 축·점·선·화살표·주석 중 무엇이 설명에 반드시 있어야 하는가? 기호와 화면 요소가 어떻게 대응하는가?
- 표현과 설명: 정적/여러 상태/GIF를 택한 이유, 처음 보여 줄 정보와 뒤에 더할 정보, 피해야 할 오해.
- 배치 관계: 그림 단독인지 본문과 두 단인지, 비교 패널인지. 기존 고정 슬롯에 맞는 종횡비와 읽기성을 고려하고 텍스트로 남길 수식을 정한다.
- 산출물과 검수: 그림 경로·원본 코드·출처, 필요한 정적 대안, 선택한 표현에 맞는 확인 기준.

예를 들어 경사하강법의 주장이 “기울기와 갱신 방향의 관계”라면 손실 곡선·현재 점·접선·갱신 화살표를 필수 요소로 지정한다. 곡선이나 이동하는 점만 만든 것으로 설명이 완성됐다고 판단하지 않는다. 수식은 고정 본문, GIF는 기존 두 단의 그림 영역에 두고, 대표 PNG에도 방향과 이전 상태를 남긴다.

## 4. 선택한 스킬로 제작

스킬은 판단·구현 지침이고 라이브러리는 파일을 만드는 도구다. 선택한 경로에 필요한 지침만 읽는다. 외부 스킬이 청중·목적·스타일을 다시 묻거나 독립 발표를 만들도록 하더라도, 기존 RVLAB 입력·양식·제작 범위·승인을 우선한다.

정량 그래프는 확인한 데이터와 변환을 코드에 연결한다. 도식은 입력·출력·화살표의 의미를 검산한다. GIF는 `rvlab-animation`에서 장면·계산·타이밍·대표 PNG를 설계한 뒤 구현한다. 필요한 실행 도구가 없으면 가능한 정적 작업을 진행하고 설치 필요성을 알리며, 자동 설치로 대신하지 않는다.

## 5. 그림과 실제 슬라이드를 함께 검수

원본 그림만 보고 끝내지 않는다. 허용된 초안 또는 내용 승인 후 빌드에서 PNG를 직접 확인한다. 자동 넘침 검사와 DPI 충족은 전달력의 증거가 아니다.

- 설명한 시각 요소가 실제로 있고, 수식·기호·숫자·그림이 같은 의미를 나타내는가?
- 처음 정한 확인 질문에 그림으로 답할 수 있는가? 불필요한 장식이나 정보가 핵심 비교를 가리는가?
- 실제 슬롯에 넣은 뒤 축·라벨·범례가 읽히고 캡션·본문과 겹치지 않는가? 원본의 글자 크기만으로 판단하지 않는다.
- 비교 그림의 축·조건·단위가 맞고, 색 없이도 선 모양·마커·라벨로 구분되는가?
- 출처와 자료의 범위가 남아 있는가? 원자료와 코드에서 값·계산을 대조했는가?
- GIF는 장면의 멈춤·반복·보간을 확인하고 대표 PNG에도 핵심 의미가 남는가? PowerPoint 재생은 정적 QA와 따로 기록했는가?

문제가 있으면 그림 원본 코드나 Markdown을 고쳐 재생성한다. 표현 자체가 설명에 맞지 않으면 설계로 돌아간다. 핵심 주장·순서·근거를 바꾸는 수정은 기존 단계 승인 절차를 따른다.
