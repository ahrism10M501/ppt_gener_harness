# 외부 사진·논문 figure 확보와 선택

연구실 내부 발표에서는 에이전트가 필요한 웹 사진과 공개 논문 figure를 직접 찾아 넣는다. 사진마다 별도 승인을 묻지 않고 기존 Stage 3 그림 계획과 Stage 4 내용 검토에 포함한다. 웹 사진은 대상·환경을 보여 주는 자료이며 발표자의 실험 결과로 설명하지 않는다.

## 웹 사진

- 먼저 task의 기존 자료를 확인하고, 부족한 사진은 제조사 공식 페이지·논문 프로젝트·데이터셋 원문을 우선 검색한다. 로봇 모델·장비·동작·실험 환경이 핵심 문장과 맞는 이미지를 고른다.
- 검색 썸네일 대신 원문 페이지에서 원본 이미지 URL을 찾아 내려받는다. HTML 응답을 이미지로 저장하지 않았는지 이미지 뷰어로 확인한다. 로그인·유료 접근을 우회하지 않는다.
- 다운로드는 task 안에서 수행한다. 원본은 `figures/external/`, 필요한 파생본은 `figures/`에 새 이름으로 저장한다. 기존 파일을 덮어쓰지 않는다. 파일명만으로 판단하지 말고 이미지를 직접 열어 모델·상황·해상도를 확인한다.
- 배경 사진·제품 사진·공개 실험 사례를 구분해 캡션에 쓴다. 발표자의 로봇 구성이나 실험 현장이라고 오해할 사진은 선택하지 않는다.

## 논문 PDF → Markdown·media

공개 PDF를 사용할 때는 저자·학회·프로젝트·arXiv 원문을 우선한다. 새 PDF는 `sources/`에 저장하며 기존 원자료를 수정하지 않는다. 새 원자료가 추가되면 기존 승인 해시가 바뀌므로 기획 자료 확보는 Stage 1 검토 전에 마친다.

```bash
uv run rvppt extract-paper tasks/<task> sources/<paper>.pdf
```

PyMuPDF4LLM으로 텍스트와 표를 Markdown으로 변환하고 이미지·벡터 그림 후보를 PNG로 추출한다. API 키·외부 문서 전송·모델 다운로드 없이 실행한다. 결과는 다음 경로에 생긴다.

```text
TASK/.build/editorial/papers/<논문명>-<PDF해시 앞 12자>/
├── paper.md       # 페이지 표식과 원문 설명, media/ 상대 링크
├── pages.json     # 원본 경로·해시·변환기 버전, 페이지별 텍스트·media 목록
└── media/         # 200 DPI PNG 후보
```

같은 PDF의 출력 폴더가 이미 있으면 덮어쓰지 않고 기존 위치를 안내한다. 이 폴더는 검토용이며 슬라이드에 직접 연결하지 않는다. 선정한 이미지를 `figures/`로 복사해야 빌드 경로와 그림 승인 해시에 포함된다. PNG 후보 파일 번호는 figure 번호가 아니며, `pages.json`의 페이지는 PDF의 1부터 시작하는 물리 페이지다.

## 캡션·본문에 따른 figure 선택

1. 슬라이드 핵심 문장에서 보여 줄 관계를 정한다. 예: “teacher–student 학습 흐름”이라면 로봇 사진보다 학습 구조 figure가 적합하다.
2. `paper.md`에서 `Figure`, `Fig.`, 해당 용어를 검색하고 캡션과 본문에서 그 figure를 설명하는 문단을 함께 읽는다. 구조·방법, 정성 사례, 정량 결과 중 어떤 역할인지 확인한다.
3. `pages.json`에서 해당 페이지의 후보를 찾고 이미지를 직접 연다. 원본 PDF의 해당 페이지도 렌더링해 figure 번호·패널·축·범례·실험 조건이 일치하는지 대조한다. 같은 페이지에 있다고 같은 figure로 간주하지 않는다.
4. 핵심 문장을 가장 잘 설명하는 그림을 선택한다. figure 번호·원문 캡션·선택 이유·필요한 패널을 기록한다. 결과 그림은 논문의 결과이며 자신의 결과와 구분한다. 캡션의 주장 범위를 넘어서는 해석이나 수치를 추가하지 않는다.
5. 원본 패널·축·범례를 보존한다. 확대·패널 분리·크롭이 필요하면 원본 후보를 보존하고 파생본에 어떤 부분을 썼는지 기록한다. 원문 캡션은 기록에 보존하고 슬라이드 캡션은 짧게 풀어 쓴다.

추출기는 그림을 놓치거나 여러 패널을 나누고, 캡션을 잘못 읽을 수 있다. 후보와 figure를 확실히 대응시킬 수 없으면 원본 PDF 페이지를 PNG로 렌더링하고 실제 경계를 보고 전체 figure 영역을 크롭한다. PDF의 삽입 이미지 하나만 뽑는 방식은 벡터 축·라벨을 잃을 수 있으므로 완전한 figure인지 확인한다. 스캔 논문은 이 기본 변환기에 OCR이 없으므로 PDF 시각 확인으로 보완하거나 필요할 때 별도 OCR 도구를 선택한다.

페이지 렌더링·크롭은 기존 PyMuPDF를 사용한다. `document[PDF페이지 - 1].get_pixmap(dpi=200)`으로 페이지를 확인한 뒤 `clip=pymupdf.Rect(...)`를 지정해 새 PNG를 만든다. 크롭 좌표는 PDF 처리용이며 슬라이드 스타일 입력에 넣지 않는다.

## 출처·배치·검수

선택한 자산은 `figures/visual-sources.yaml`에 기록한다. 웹 사진이면 figure·페이지·원문 캡션을 생략할 수 있다. 표시된 이용 조건을 기록하고 없으면 `미확인`으로 둔다. 내부 발표용 사용을 공개 배포 허가로 간주하지 않는다.

```yaml
- asset: figures/viral-training.png
  kind: paper-figure
  source_file: sources/viral.pdf
  source_sha256: <pages.json의 원본 해시>
  source_url: <원문 PDF 또는 DOI URL>
  provider: <논문 저자·연도>
  figure: <원본 Figure 번호와 패널>
  pdf_page: <1부터 시작하는 PDF 페이지>
  original_caption: <확인한 원문 캡션>
  selected_for: <슬라이드 ID와 핵심 문장에 맞는 이유>
  original_asset: <추출 후보 경로 또는 보존한 원본 이미지>
  changes: <없음 또는 크롭·패널 선택 내역>
  usage_terms: <표시된 이용 조건 또는 미확인>
```

`slides.md`에는 `![짧은 설명](figures/viral-training.png)`로 삽입하고, `::: source`에 저자/기관·연도·Figure 번호·DOI/URL을, `::: notes`에 전체 서지·원문 캡션·변형 내역을 넣는다. 연구실 내부 발표라는 사용 맥락은 기존 interview/brief에 기록한다.

기존 고정 그림 슬롯을 사용하며 좌표·폰트·색을 지정하지 않는다. `lint`와 요청받은 `build` 후 PNG에서 글자·축·범례의 크기, 크롭 누락, 출처 가독성을 확인한다. 의미 선택과 최종 배치는 이 절차를 읽는 에이전트가 수행하며 `extract-paper` 명령 자체는 추출만 한다.
