# 인터뷰 질문 가이드

아직 확인되지 않은 의도를 탐색할 때 읽는다. 질문 예시는 자료와 청중에 맞게 바꾼다.

## 질문 묶음과 답변에 따른 분기

새 질문 묶음은 **아직 확인되지 않은 3~5개 항목**을 고른다. 질문마다 구체적 상황, 2~3개의 짧은 선택지, 자유 입력을 제공한다. 선택지가 답을 제한하거나 에이전트 가정을 사실로 암시하지 않게 한다. 질문 도구가 있으면 질문을 함께 제시한다. 질문을 채우기 위해 이미 답한 항목을 반복하지 않는다. 남은 항목이 묶음을 만들 만큼 없으면 추천안과 미해결 항목을 승인 요약에 포함한다.

| 알아낼 것 | 구체적 질문 예 | 답변이 모호할 때 확인할 것 |
| --- | --- | --- |
| 청중 | 실제 참석자는 누구이며, ACT/BC를 어느 정도 아는가? | 직함 대신 실제 설명이 필요했던 최근 장면·사전 지식 |
| 목적 | 발표 뒤 청중이 무엇을 이해·판단·결정해야 하는가? | “진행 공유”라면 어떤 피드백/결정을 받고 싶은지 |
| 핵심 재료 | 가장 보여주고 싶은 결과와 직접 뒷받침하는 파일은? | 측정 조건·비교 기준·표본 수·결과가 보이는 실제 위치 |
| 성공/실패 | 좋은 발표의 기준과 반드시 피할 오해는? | “성능이 좋다”가 학습/검증/실환경 중 어디까지인지 |
| 제약 | 시간·발표 유형·필수/제외 내용은? | 시간이 부족할 때 무엇을 남기고 무엇을 포기할지 |

답변마다 다음 질문이 필요한지 판단한다. 일반적인 질문지를 끝까지 읽지 않는다.

- **근거가 없는 주장:** 주장에 해당하는 실제 결과·사례를 요청한다. 없으면 메시지를 좁히거나 한계/향후 검증으로 표시한다.
- **숨은 전제:** 예를 들어 “학습 loss 감소 = 실제 성공률 향상”인지 구분한다. 근거와 반례를 짚고 사용자가 동의한 전제만 확정한다.
- **상충하는 요구:** 예를 들어 5분 안에 모든 ablation을 설명하려는 경우, 핵심 결정에 필요한 항목과 자료로 넘길 항목을 비교한다.
- **주제 미정:** topic은 탐색 중 TBD로 둔다. 결과·자료·피드백 목적부터 모으고 Stage 2에서 근거 있는 후보 2~3개를 제시한다.
- **같은 모호함이 지속:** 같은 항목에 대한 추가 확인은 최대 두 차례다. 이후 근거 있는 후보와 추천안, 선택에 따른 메시지 차이를 제시한다. 핵심 근거가 없는데 임의로 승인 처리하지 않는다.
- **질문을 줄여 달라는 요청:** 기존 자료/답변을 재사용하고 추천안을 제시한다. 남은 추정을 명시하며 질문 생략을 내용 승인으로 해석하지 않는다.

## 단계별로 더 물을 것 (같이 만들기)

| 단계 | 언제 | 질문 예 |
| --- | --- | --- |
| Stage 1 | 첫 묶음의 답을 받은 뒤 | “30분에 질의응답이 포함되나요?”, “Cosmos는 소개만 할까요, Policy까지 자세히 볼까요?”, “지난 발표에서 받은 질문이 있나요?” |
| Stage 2 | 후보를 비교하기 전 | “개념 설명과 최신 사례 중 어느 쪽에 시간을 더 쓸까요?”, “꼭 빼고 싶은 주제가 있나요?” |
| Stage 3 | 목차 전체를 쓰기 전에 Chapter 뼈대와 장수를 먼저 보여 주며 | “이 순서와 장수가 맞나요?”, “이미 가진 그림이나 직접 돌려 본 결과가 있나요?”, “이 그림 12장을 다 만들 수 있나요, 논문 그림을 출처와 함께 쓸까요?” |
| Stage 4 | 섹션 하나를 쓴 뒤 | “S11 표에 Transfer를 넣을까요?”, “이 수치는 논문 표 그대로 옮길까요?”, “이 부분을 직접 경험한 사례로 바꿀 수 있나요?” |

자료로 답할 수 있으면 묻지 않는다. 한 번에 3~5개를 넘기지 않고, 답을 기다리는 동안 이미 확정된 부분은 계속 작성한다.

`interview.md`의 질문 기록에는 ID·질문 이유·선택지·실제 답변·추가 확인 횟수·결론을 남긴다. `open_items`와 `assumptions`를 함께 갱신한다. 답변이 기존 문서와 충돌하면 이전 요구를 조용히 덮어쓰지 말고 무엇이 바뀌었는지 재진술한다.
