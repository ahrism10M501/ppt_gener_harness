# 인터뷰 질문 가이드

아직 확인되지 않은 의도를 탐색할 때 읽는다. 질문 예시는 자료와 청중에 맞게 바꾼다.

## 질문 묶음

한 번에 몇 개(보통 3~5개)를 묶어 묻는다. 질문마다 구체적 상황, 짧은 선택지 몇 개, 자유 입력을 준다. 선택지가 에이전트 가정을 사실처럼 암시하지 않게 한다. 질문 도구가 있으면 사용한다. 남은 항목이 적으면 따로 묻지 말고 추천안과 함께 단계 보고에 넣는다.

| 알아낼 것 | 구체적 질문 예 | 답변이 모호할 때 확인할 것 |
| --- | --- | --- |
| 청중 | 실제 참석자는 누구이며, ACT/BC를 어느 정도 아는가? | 최근에 설명이 필요했던 장면·사전 지식 |
| 목적 | 발표 뒤 청중이 무엇을 이해·판단·결정해야 하는가? | "진행 공유"라면 어떤 피드백/결정을 받고 싶은지 |
| 핵심 재료 | 가장 보여 주고 싶은 결과와 그것을 뒷받침하는 파일은? | 측정 조건·비교 기준·표본 수 |
| 성공/실패 | 좋은 발표의 기준과 반드시 피할 오해는? | "성능이 좋다"가 학습/검증/실환경 중 어디까지인지 |
| 제약 | 시간·발표 유형·필수/제외 내용은? | 시간이 부족할 때 무엇을 남길지 |

## 답변에 따른 분기

답마다 다음 질문이 필요한지 판단한다. 질문지를 끝까지 채우지 않는다.

| 사용자 답변 또는 관찰 | 다음 행동 |
| --- | --- |
| "교수님께 진행 보고" | 받고 싶은 피드백/결정과 교수님의 사전 지식을 확인 |
| "loss가 내려가니 성공률이 오른다" | 학습 지표와 독립 평가 결과를 분리하고 메시지 범위를 확인 |
| "결과가 좋다" | 같은 조건의 비교·표본 수·보여 줄 결과 파일 확인 |
| "5분, 결과/방법/모든 ablation 포함" | 핵심 목적에 맞는 우선순위를 추천하고 본문/보조 자료를 구분 |
| "주제는 아직 모르겠다" | TBD로 두고 결과·자료·판단 목적부터 탐색, Stage 2에서 후보 제시 |
| "질문을 줄여 달라" | 기존 근거 재사용, 추천안·가정·미해결을 제시. 질문 생략을 승인으로 보지 않음 |
| 같은 모호함이 계속됨 | 근거 있는 후보와 추천안, 선택에 따른 메시지 차이를 제시 |

근거 없는 주장은 해당하는 결과를 요청하고, 없으면 메시지를 좁히거나 한계로 표시한다. 숨은 전제는 근거와 반례를 짚고, 사용자가 동의한 전제만 확정한다.

## 같이 만들기에서 더 물을 것

| 단계 | 언제 | 질문 예 |
| --- | --- | --- |
| Stage 1 | 첫 묶음의 답을 받은 뒤 | "30분에 질의응답이 포함되나요?", "Cosmos는 소개만 할까요, Policy까지 볼까요?", "지난 발표에서 받은 질문이 있나요?" |
| Stage 2 | 후보를 비교하기 전 | "개념 설명과 최신 사례 중 어느 쪽에 시간을 더 쓸까요?", "꼭 빼고 싶은 주제가 있나요?" |
| Stage 3 | Chapter 뼈대와 장수를 먼저 보여 주며 | "이 순서와 장수가 맞나요?", "이미 가진 그림이나 직접 돌려 본 결과가 있나요?" |
| Stage 4 | 섹션 하나를 쓴 뒤 | "이 표에 Transfer를 넣을까요?", "이 수치는 논문 표 그대로 옮길까요?", "직접 경험한 사례로 바꿀 수 있나요?" |

답을 기다리는 동안 이미 확정된 부분은 계속 작성한다. `interview.md`에는 주요 질문과 결론을 남기고 `open_items`와 `assumptions`를 갱신한다. 답이 기존 문서와 충돌하면 이전 요구를 조용히 덮어쓰지 말고 무엇이 바뀌었는지 재진술한다.
