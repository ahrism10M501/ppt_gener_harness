# RVLAB 발표 인터뷰

발표 의도를 확인하고 Stage 1~3 문서를 사용자 검토와 승인이 가능한 상태로 만든다.

## 시작

저장소 루트의 `AGENTS.md`, `docs/workflow.md`, `docs/schemas.md`를 읽는다. 발견 경로가 symlink이면 실제 `skills/` 위치를 기준으로 저장소 루트를 찾는다.

사용자가 지정한 task와 원자료를 재사용하고 `sources/`는 수정하지 않는다. 연구자의 초안 PPT도 `sources/`의 자료로 읽는다. 새 task는 `uv run rvppt new <slug> --title <제목>`으로 만들며 표지 인적사항은 `profile.yaml`에서 온다. `uv run rvppt status tasks/<task>`의 `next_stage`와 `next_document`부터 재개하며 기존 답변과 유효한 승인을 보존한다.

## 자료와 질문

자료에서 먼저 답을 찾고 `interview.md`에 다음을 구분한다.

- **자료 사실:** 실제 관찰·수치·설정, 근거 파일과 위치, 주장 범위.
- **사용자 요구:** 직접 밝힌 목적·취향·제약과 짧은 인용.
- **에이전트 추정:** 자료로 추론한 청중 지식·우선순위·스토리. 동의 전에는 사용자 요구로 기록하지 않는다.
- **미해결:** 모르는 사실·부족한 근거·상충하는 요구. 핵심 주장이나 선택을 바꾸는 항목은 `open_items`의 `blocking: true`로 기록한다.

모르는 항목만 3~5개씩 묻고 질문마다 짧은 선택지와 자유 입력을 제공한다. 이미 확인한 내용을 반복하거나 질문 수를 채우려고 질문하지 않는다. 답이 충분하면 이해한 내용과 남은 추정을 재진술해 승인 대상으로 제시한다.

## 진행 방식 선택

새 task의 첫 질문 묶음에 진행 방식을 함께 묻고 답을 `interview.md`의 사용자 요구로 기록한다. 사용자는 언제든 “알아서 해”·“더 물어봐”로 바꿀 수 있다.

- **같이 만들기(추천):** 단계마다 질문한다. Stage 1에서 한 묶음으로 끝내지 않고, 발표 내용·시간·범위를 바꾸는 항목이 남아 있으면 다음 묶음을 묻는다. Stage 2·3·4에서도 문서를 쓰다가 연구자만 아는 것이 나오면 모아서 묻는다.
- **핵심만:** Stage 1 질문 뒤에는 추천안으로 진행하고 단계 승인 때만 확인한다.

같이 만들기에서는 다음을 `assumptions`로 넘기지 말고 묻는다.

- 시간 배분과 질의응답 포함 여부, 슬라이드 분량
- 다룰 사례·모델·실험의 선정과 깊이, 뺄 내용
- 연구자가 이미 가진 그림·결과·코드·초안, 직접 써 보거나 구현한 것
- 청중이 특히 궁금해하거나 지난 발표에서 받은 질문
- 근거가 약한 주장을 넣을지, 좁힐지

사소한 표현 선택이나 자료로 확인되는 사실은 묻지 않는다. 단계별 질문 예는 [질문 가이드](references/interview-guide.md)에 있다.

질문을 구성하거나 모호한 답변·부족한 근거·상충하는 요구를 처리할 때 [질문 가이드](references/interview-guide.md)를 읽는다.

## 단계별 결과물

1. **`plan/interview.md`:** 청중·목적·핵심 근거·성공/실패 기준·제약·전제를 정리한다. 끝에는 누구에게, 어떤 결과로, 어떤 판단을 받으려는지 재진술한다. 중요한 미해결 항목은 해결하거나 주장 범위를 좁힌다.
2. **`plan/brief.md`:** 메시지와 스토리라인 후보 2~3개에 근거·장단점·추가 자료를 붙이고 추천안을 제시한다. 사용자 선택을 반영하고 최종 `review`의 메시지·순서를 선택한 후보와 일치시킨다. 메시지를 고르면 **표지 제목·부제 후보 2~3쌍**을 제안해 함께 묻는다. RVLAB 표지는 제목 아래 노란 부제(한 줄 설명이나 영문 제목)가 있다. 고른 값은 `slides.md`의 `deck`에 반영한다.
3. **`plan/outline.md`:** 슬라이드 ID·섹션·토픽·핵심 문장(headline)·근거·예상 시간과 그림 제안(figure)을 정리한다. 토픽은 상단 바·목차에 실릴 짧은 이름, 핵심 문장은 슬라이드의 결론이다. 발표 유형별 구성은 [랩미팅 가이드](../rvlab-ppt/references/lab-meeting.md)를 참고한다. 배경 지식·순서·시간·한계와 반론을 확인하며 좌표·색·폰트·레이아웃을 묻지 않는다.

문서의 frontmatter와 `review` 형식은 `docs/schemas.md`를 따른다. Stage 3 승인 후 Stage 4 본문·제작·QA는 [rvlab-ppt](../rvlab-ppt/SKILL.md)를 따른다. 승인된 목차의 섹션·토픽·핵심 문장 순서를 유지한다.

## 승인과 재개

각 단계가 끝나면 **파일 링크만 주지 말고 채팅에 단계 보고를 쓴다.** 사용자가 파일을 열지 않고도 판단할 수 있어야 한다.

- **Stage 1:** 누구에게·무엇을·어떤 판단을 받으려는지 세 줄 재진술, 자료로 확인한 것과 추정한 것, 남은 질문.
- **Stage 2:** 후보마다 한 줄 메시지와 흐름(섹션 순서), 추천과 그 이유, 표지 제목·부제 후보.
- **Stage 3:** 아래 순서로 쓴다.
  1. 분량: 본문 N장 + 자동 M장(표지·목차·섹션 K장·감사합니다) = 총 T장, 예상 시간.
  2. 표지(제목·부제·날짜·발표자)와 목차: Chapter마다 섹션 부제, 토픽, 장수·시간을 한 줄씩. 실제 표지·목차·섹션 슬라이드에 실릴 모양 그대로 쓴다.
  3. 슬라이드별 표: `ID | 상단 바 | 핵심 문장 | 들어갈 내용(불릿 요지·그림·표·수식)`.
  4. 연구자에게 요청할 그림 목록과 준비 부담이 큰 부분.
  5. 추정·미해결, 그리고 결정해 달라는 질문(같이 만들기면 질문 도구로).
- **Stage 4:** 장별로 바뀐 점, 남은 그림 요청, 미리보기 PNG.

보고 끝에 문서 링크와 `status`의 `review_hash`를 붙여 명시적으로 승인받는다. 다른 질문에 대한 “예”, 추천안 선택, 시간 경과를 단계 승인으로 해석하지 않는다.

승인 뒤 `uv run rvppt approve tasks/<task> --stage N --expected-hash <검토한-review_hash>`를 실행한다. 입력 변경으로 실패하면 변경점을 보여 다시 검토한다. 승인 필드를 직접 수정하지 않는다. 상위 입력이 바뀌면 `status`가 가리키는 단계부터 재개한다.

## 사용하는 코드

질문 선택과 답변 해석은 이 스킬의 지침으로 수행한다. 문서 검증·해시·승인 무효화는 기존 `tools/rvppt/state.py`, 명령 실행은 `tools/rvppt/cli.py`를 재사용한다. 인터뷰 전용 `scripts/`나 질문 생성 명령은 현재 없다. 질문과 근거의 타당성은 에이전트와 사용자가 검토한다.

참고한 인터뷰 방식과 고정 버전은 `docs/workflow.md`에 있다. 외부 프레임워크의 통신·telemetry·추가 승인 절차는 실행하지 않는다.
