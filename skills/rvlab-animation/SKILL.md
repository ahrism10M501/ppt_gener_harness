# RVLAB 교육 애니메이션

공통 [시각 설계 절차](../rvlab-ppt/references/visual-planning.md)에서 정한 주장·근거·표현·배치를 받아 움직임을 상세 설계한다. 사용자가 GIF를 직접 요청한 경우에도 그 의도와 정적 대안을 확인한다. 발표 제작은 [rvlab-ppt](../rvlab-ppt/SKILL.md), 승인·자료 보존·디자인은 저장소의 `AGENTS.md`·`DESIGN.md`를 따른다. 발견 경로가 symlink이면 실제 `skills/` 위치를 기준으로 저장소 루트를 찾는다.

## 표현 선택

표현 선택의 공통 기준은 시각 설계 절차를 따른다. 변화의 방향·순서·속도·동시성 중 어떤 정보가 정적 그림에서 사라지는지 한 문장으로 쓴다. 설명할 변화가 없으면 정적으로 제안한다. 발표자가 단계마다 멈춰 설명해야 하면 여러 정적 상태를 우선 검토한다. 사용자가 GIF 제작을 명시했다면 그 의도를 반영하되 정보량이 많은 설명은 여러 장이나 짧은 장면으로 나눈다. 같은 제작 허가를 다시 묻지 않는다. 이 요청은 자료·숫자·연구 결과를 새로 만들어도 된다는 뜻이 아니다.

## 제작 전 storyboard

자료에서 확인한 청중 수준·목적·정의·수식·결과를 재사용한다. 중요한 미확인 정보만 질문하며, 이미 승인된 내용은 다시 묻지 않는다. task의 `plan/animation.md`에 아래 항목을 기록하고 해당 슬라이드의 `plan/outline.md`·`slides.md` 노트와 연결한다. 별도 승인 단계를 만들지 않고 기존 단계의 검토에 포함한다.

```yaml
slide_id: slide-03
audience: 청중이 이미 아는 용어와 아직 모르는 개념
claim: 이 장면을 보고 이해해야 할 문장 하나
motion_reason: 연속 변화가 필요한 이유와 정적 대안
evidence: sources/ 경로 또는 합성 교육 예제임을 명시
misconception: 관객이 혼동할 수 있는 전제나 해석
visual_mapping: 기호·색·선·위치가 각각 뜻하는 것
equations: 화면 요소와 계산식의 대응 및 가정
beats:
  - state: 처음 관찰할 상태
    change: 변하는 요소와 고정되는 요소
    explanation: 발표자가 말할 설명
    hold: 읽고 생각할 시간을 둘 지점
poster: 정지해도 claim을 이해할 수 있는 상태
playback: 단발/반복과 끝 상태·재시작 구분
```

- 한 장면에 주장 하나를 둔다. 기호를 도입하고 상태를 보여 준 뒤 변화·결과 순으로 설명한다.
- 수식의 변수와 실제 움직이는 점·선·축을 대응시킨다. 관객이 아직 모르는 기호를 동시에 여러 개 추가하지 않는다.
- 속도는 읽을 시간에 맞춘다. 수치·기호가 바뀌는 순간과 결과를 확인하는 순간에는 멈춤을 둔다.
- GIF의 재생 시간은 물리 시간·학습 속도와 다를 수 있다. 실제 시간이 중요한 경우 화면에 시간/반복 번호와 재생 배율을 표시한다.
- 흔히 짧은 장면은 8–20초, 12–24fps로 시작하지만 이는 추천값이다. 계산 단계·글자 가독성·파일 크기를 보고 조정하며 고정 검증 기준으로 쓰지 않는다.
- 반복 시 끝에서 처음으로 돌아가는 순간을 실제 역방향 과정으로 오해하지 않도록 정지·구분 표시를 넣거나 단발 재생한다. 시각 효과를 위해 왕복시키지 않는다.

## 도구와 외부 스킬

이미 있는 도구와 제작 패턴을 사용한다. 간단한 2D 그래프는 Matplotlib·Pillow, 좌표 변환·수식과 도형의 연속 관계는 Manim CE가 적합하다. Manim 설치·사용 자체가 목적은 아니다. 라이브러리 지원·실제 렌더 옵션은 설치한 버전에서 확인한다.

외부 스킬은 고정 버전 원문을 수정하지 않고 필요한 역할만 선택해 읽는다.

| 스킬 | 읽을 때와 사용할 범위 |
| --- | --- |
| [manim-composer](../manim-composer/SKILL.md) | Manim 장면을 기획할 때: 청중 수준·오해·장면 순서·설명 흐름 |
| [manimce-best-practices](../manimce-best-practices/SKILL.md) | Manim CE를 구현·디버그할 때: Scene·애니메이션 API·렌더 호환성. ManimGL 문법과 혼용하지 않음 |
| [scientific-visualization](../scientific-visualization/SKILL.md) | 정량 그래프를 만들 때: 축·불확실성·색 구분·내보내기·그림 검수 |
| [scientific-slides](../scientific-slides/SKILL.md) | 논문 그림을 발표용으로 단순화할 때: figure의 핵심 메시지·주석·단계적 공개·시각 검토 참고 자료 |

외부 스킬의 테마·색·표지·전체 슬라이드 생성 규칙으로 RVLAB 마스터를 바꾸지 않는다. `scientific-slides`의 이미지 생성 경로는 외부 API를 쓰며, 이 로컬 GIF 제작에는 필요하지 않다. 해당 스킬의 전체 이미지 슬라이드 제작 경로를 기본값으로 선택하지 않는다. 스킬이 없으면 자동 다운로드하지 않고 현재 도구로 가능한 작업을 진행한다. sudo나 시스템 설치가 실제로 필요하면 구체적인 명령과 이유를 제시해 확인받는다.

## 내용과 미감

- 흰 배경·검정 글자·회색 보조 요소·RVLAB 파랑 강조를 사용한다. 추가 구분은 선 모양·마커·직접 라벨로 한다. 색 의미를 장면 중간에 바꾸지 않는다.
- 도식 상자는 직각으로 만들고 선·화살표·간격을 일정하게 한다. 둥근 카드·그라데이션·그림자·장식 아이콘·다채로운 강조는 쓰지 않는다. 원·곡선이 수학적 의미를 가진 경우에는 그 의미에 맞게 쓴다.
- 한 figure에 읽어야 할 요소를 최소화한다. 정의·수식·짧은 설명은 가능한 한 슬라이드의 편집 가능한 본문에 남긴다.
- 그래프는 `docs/design/rvlab.mplstyle`을 사용하고 축·단위·범례를 명시한다. 생략한 축·정규화·스케일 변경은 설명한다. 비교 장면 사이 축 범위를 고정한다.
- 모든 움직임과 숫자는 실제 계산에서 가져온다. 경로를 보기 좋게 꾸며 수렴·성공을 주장하지 않는다. 반복 최적화라면 목적함수·미분·갱신식·초기값·학습률·정지 조건을 기록하고 검산한다.
- 교육용 합성 예제는 캡션과 노트에 합성임을 표시한다. 그 결과를 실험 성능이나 일반적 보장으로 표현하지 않는다. 목적함수·모델·데이터·학습 규칙을 구분한다.

## 파일과 PPT 계약

- 같은 task의 `figures/foo.gif`와 `figures/foo.png`를 함께 만든다. PNG는 선택한 대표 상태이며 GIF와 픽셀 너비·높이가 같아야 한다. 이름만 같은 다른 그림이나 임의 첫 프레임을 쓰지 않는다.
- 계산·렌더 원본 `.py`와 사용한 파라미터·데이터 출처를 task 안에 보존한다. 수정 불가 원자료는 `sources/`, 생성 스크립트는 `figures/`에 두고 임시 렌더는 `.build/animation/`에 격리한다. 고정한 난수 시드를 기록한다.
- Markdown 삽입은 `![짧은 설명](figures/foo.gif)`이다. 기존 단독 figure 또는 본문+figure 두 단 레이아웃을 사용한다. 좌표·폰트·색·크기를 `slides.md`에 지정하지 않는다.
- 최종 PPTX에는 원래 GIF 미디어를 보존하고 PDF·미리보기 PNG에는 같은 stem의 대표 PNG를 사용한다. PPTX의 GIF 보존과 실제 PowerPoint 재생은 다른 검증이다.
- PNG만 보아도 핵심 설명과 최종 상태를 이해할 수 있게 만든다. 필요하면 이전 상태의 흔적·이동 방향·반복 번호를 추가하거나 정적 단계 그림을 별도 슬라이드로 둔다.

## 검수와 전달

1. 계산식·갱신값·표시 숫자를 대조하고 필요한 작은 수치 검사를 실행한다. 움직이는 요소만으로 원인·결과를 잘못 암시하지 않는지 확인한다.
2. 처음·중간·마지막·대표 프레임과 GIF 재생을 직접 확인한다. 글자 겹침·잘림·읽을 시간·축 흔들림·재시작 오해를 고친다.
3. `uv run rvppt lint TASK`, `build TASK`, `preview TASK` 후 슬라이드 PNG와 PDF의 대표 상태·캡션·배치를 직접 확인한다. 요청된 초안은 초안으로 전달하며 내용 승인 상태를 바꾸지 않는다.
4. PPTX ZIP의 GIF 미디어와 원본을 비교하고 정적 렌더가 PNG를 사용했는지 확인한다. 실제 PowerPoint에서 재생을 확인하지 않았다면 그 점을 기록하며 검증 완료로 쓰지 않는다.
5. 전달 시 어떤 변화를 보여 주는지, 합성/실측 여부, 대표 PNG와 원본 스크립트, 검증 결과와 남은 한계를 알려 준다.
